Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat は、作業をローカルでリアルタイムに実行するため、すべてのツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または却下できます。エディターを離れずに追加のプロンプトを送信し、作業を調整したり、拡張したりすることもできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントを誘導し、ハイコントラストモードに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加してほしいとのことです。新たに会話を始める代わりに、既存のセッションを誘導して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイルの編集内容は、差分と **Keep** / **Undo** の操作ボタンとともにチャットに表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの操作を確認します。ファイルの読み込み、編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を元に戻し、エージェントにもう一度作業させます。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したファイルをまとめて確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツールの使用許可を求められると、エージェントは一時停止し、**Allow** のプロンプトを表示します。実行してもよいコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、行った変更をまとめたメッセージが表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードを実装したら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは、変更したコンポーネント、スタイルの方針、設定に使った local storage のパターンなど、前の作業のコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業を調べて、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を1つずつレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合は (たとえば、好みと異なる方法で切り替え UI をリファクタリングしようとする場合)、チャット入力欄の横にある **Stop** ボタンで停止して、明確な追加メッセージを送信します。

> [!TIP]
> 作業中のセッションを誘導すると、最初からやり直すよりも速く進められます。追加のプロンプトで調整を依頼できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」のような変更や、「3つ目の切り替えを追加せず、ライトモードを既存の設定パネルに統合する」のような方向修正、あるいは「両方の切り替えにキーボードショートカットも追加する」のような範囲の拡張が可能です。

## 作業セットをレビューする

コミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントで指定したアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage を使った設定の保持など) が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で進行中のセッションを監視して誘導しました。ファイル編集のたびにレビューし、変更を採用または却下し、コンテキストを失わずに作業を拡張する追加プロンプトを送りました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 追加プロンプトで作業中のセッションを誘導しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボ全体でローカルのカスタムエージェントが生成した変更をレビューします。
